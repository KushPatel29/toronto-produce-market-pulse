# Power BI semantic model (as code)

`MarketPulse.SemanticModel/` is the model in **TMDL**, the text format Power BI Desktop uses for Power BI Projects (`.pbip`). It is generated by `python build_powerbi_model.py` from the pipeline outputs, so tables, columns and measures cannot drift from the CSVs, and every change shows up as a readable diff in Git.

**Open it:** Power BI Desktop > File > Open > `powerbi/MarketPulse.pbip`, then Refresh. Data loads from the public GitHub copy of `outputs/` through the `SourceRoot` parameter (Transform data > Edit parameters to point it at your own rebuild). The report shell has one blank page; the model is the deliverable.

## Tables

| Table | Grain | Rows | Source |
|---|---|---:|---|
| `fact_sales_price` | item x customer segment x week | 27,928 | replayed prices on real costs |
| `fact_market_price` | item x week | 7,199 | real Toronto terminal prices, CAD |
| `fact_shipments` | item x channel x week, 2019 and 2023 | 6,555 | **synthetic** volumes and promotions on real costs |
| `fact_promotion` | promotion event | 105 | **synthetic** events, evaluated against a baseline |
| `dim_item` | basket item | 30 | |
| `dim_segment` | customer segment and terms | 4 | |
| `dim_date` | report week | 265 | |
| `security_user_segment` | user email x segment | 8 | calculated table for row-level security (example emails) |

Seven single-direction, many-to-one relationships join the facts to the dimensions (`relationships.tmdl`).

## Measures (38, in display folders)

- **Pricing:** Revenue, COGS, Gross Margin, GM %, Breach Rate, Price Changes
- **Margin variance:** GM at Target, Margin Variance = Cost Timing + Price Hold, and a `Variance Check` that must be 0
- **Market:** Avg Terminal Price (CAD), change vs prior year
- **Revenue growth:** Net and List Revenue, Discounts & Promotions, Discount Rate, Shipment GM %, Promo Share of Cases
- **Price-volume-mix:** the 2019 to 2023 gross margin bridge (Volume, Mix, List Price, Discounts & Promotions, Cost) with a `PVM Check` that must be 0. The bridge respects slicers, so it can be cut by category or channel.
- **Promotions:** Trade Spend, Net Incremental Margin, Promo ROI, Events Paid Back, Median Break-even Lift, Lift Estimate Error

## Security and language

- **Row-level security:** a static role (`Contracts team`) and a dynamic role (`Segment manager`) that filters `dim_segment` to the segments mapped to `USERPRINCIPALNAME()`. Test with Modeling > View as.
- **French (fr-CA) translations** for every table, column and measure in `cultures/fr-CA.tmdl`, so a bilingual report shows French captions to French-locale viewers.

## How it is checked

`tests/test_powerbi_model.py` checks that the committed TMDL matches the generator, every `table[column]` and `[measure]` reference in the DAX resolves, every relationship key is unique on the one side and complete on the many side, and the PVM measures' algebra reproduces the Python bridge to the cent. Those are static checks; DAX itself is evaluated only when the model is opened in Power BI Desktop.

`measures.dax` lists the same measures as plain DAX for reading or for pasting into another model.
